# Публикация Yumurta Seller в App Store — как это работает и где грабли

Записано 25.09.2026 после выпуска 1.0.1, который встал дважды подряд.
Приложение: `ru.marketplace.business`, App Store ID **6809221577**, язык карточки — русский.

## Путь кода до сборки

Файлы из папки `7 IOS-seller` на компьютере **сами по себе никуда не едут**. Порядок такой:

1. файлы заливаются в GitHub-репозиторий;
2. Codemagic подтягивает репозиторий и собирает из него (в логе видно `/Users/builder/clone`).

Отсюда правило: правка в локальной папке до сборки не доходит. Если после «исправления»
CI ведёт себя ровно как раньше — первым делом проверяем, залит ли файл в репозиторий,
а не ищем ошибку в коде.

## Процессы в codemagic.yaml

| Процесс | Что делает |
|---|---|
| `ios-check` | собирает под симулятор без подписи — только проверка компиляции |
| `ios-testflight` | собирает, подписывает, загружает в App Store Connect, на проверку не подаёт |
| `ios-release` | то же плюс заявка в App Store и выпуск сразу после одобрения (подача — в пост-обработке Codemagic, вкладка Publishing) |
| `ios-submit-draft` | руками, только после неудачной подачи: довести зависший черновик заявки |

«Загрузить сборку в App Store Connect» и «подать на проверку» — два разных действия.
Второе включается ключом `submit_to_app_store`.

## Грабля 1. Заявка на обновление без «Что нового»

```
409 ... You must provide a value for the attribute 'whatsNew'
```

Сборка загружается и обрабатывается нормально, падает только подача. Apple требует текст
как минимум в языке карточки по умолчанию.

Как закрыто: шаг «Что нового» перед публикацией берёт текст из `release-notes/ru.txt`
(или из переменной `APP_STORE_WHATS_NEW`), обрезает до 4000 символов по границе строки и
пишет **во все** локализации карточки — из ответа API не видно, какая из них по умолчанию.
Уже заполненный руками текст не перетирает (для перезаписи — `APP_STORE_WHATS_NEW_FORCE=1`).

Перед каждым выпуском правим `release-notes/ru.txt` — и всё.

Отдельная тонкость: искать карточку версии только по номеру нельзя. Публикация умеет
переименовать карточку (у нас карточка «1.1» стала «1.0.1») уже ПОСЛЕ шага, и поиск по
номеру находил пустоту. Поэтому если карточки с нужным номером нет, берём единственную
редактируемую (`PREPARE_FOR_SUBMISSION`, `*_REJECTED`) — публикация переиспользует её же.

## Грабля 2. Лимит в пять заявок

```
409 ... ReviewSubmission creation concurrency limit is reached
        maximum limit=5 of concurrency has reached
```

Apple держит не больше пяти одновременных заявок на приложение, и **черновики**
(`READY_FOR_REVIEW` — созданные, но не отправленные) тоже занимают место. Каждая неудачная
публикация оставляла по черновику: Codemagic успевал СОЗДАТЬ заявку и падал следом на
пустом «Что нового». Пять попыток — лимит выбран, и больше не создаётся ни одна заявка,
даже полностью исправная.

Чего НЕ делать: пытаться отменить черновик через API. Apple отвечает
`409 Resource is not in cancellable state` — отмена разрешена только для уже отправленных
заявок. Ключ `cancel_previous_submissions` тоже не помогает: он трогает только
`WAITING_FOR_REVIEW`, `IN_REVIEW`, `UNRESOLVED_ISSUES`.

Как закрыто: не создаём шестую заявку, а **переиспользуем черновик** — кладём в него версию
(`review-submission-items create`) и подтверждаем (`review-submissions confirm`). Заявка
уходит на проверку, черновик перестаёт занимать лимит, завал разбирается по одному за выпуск.

**Поправка 21.10.2026.** Раньше шаг стоял в блоке `publishing: scripts:` процесса `ios-release`
в расчёте, что к этому моменту сборка уже прицеплена к карточке. Это неверно: подача
(`submit_to_app_store`, `cancel_previous_submissions`) у Codemagic идёт в **пост-обработке** —
асинхронно, уже после всех шагов процесса (документация Codemagic, раздел «Post-processing»).
Шаг выполнялся раньше подачи: заявки ещё нет, а при старом пустом черновике он мог отправить
на проверку прошлую сборку. Теперь это отдельный процесс **`ios-submit-draft`** («довести
зависшую заявку»): запускать руками, только если подача упала (вкладка **Publishing** у сборки)
и остался черновик, — сначала проверив в App Store Connect, что в версии нужная сборка.

Ручной путь на тот же случай: страница версии в App Store Connect → «Добавить на проверку» →
«Отправить на проверку». Снять лишние заявки — **Приложения → App Review → Отправки**.

## Правила для шагов в codemagic.yaml

* Шаг-обслуживание (метаданные, чистка) **никогда не роняет сборку**: сообщил о заминке и `exit 0`.
* Все данные для выпуска — в репозитории, а не в настройках Codemagic. Переменная,
  которую забыли завести, выглядит в логе как «шаг молча ничего не сделал».
* Блочный скаляр YAML рвётся на любой строке с нулевым отступом. Многострочный python
  внутри `script: |` не писать — только однострочники через `python3 -c "..."`.
* Разбор JSON от `app-store-connect --json` делать устойчивым: и массив, и `{"data": [...]}`,
  и одиночный объект.
* Перед заливкой: разобрать yaml парсером, вытащить скрипт и проверить `sh -n`, затем
  прогнать его с подставным `app-store-connect` в `PATH` по всем ветвям.
